# 动态领域时效门禁

在软件、平台、工具、法律、标准、医学、金融或其他会持续变化的领域，建立学习契约前执行本门禁。它防止旧地图或一次功能扫描被误当成“最新研究”。

## 1. 判定研究范围

- 以当前会话日期作为目标 `as_of`，不能沿用模型知识截止日。
- 读取现有地图的 `as_of`。有地图时从该日期做增量刷新；没有地图或缺少最新轨时，按 `anything-research` 的领域制图深度模式重建。
- 即使地图生成于近期，也要联网检查从旧 `as_of` 到当前日期是否出现变化。只有可证明没有实质变化，才能复用其节点。
- 无法联网或无法读取关键一手资料时，门禁失败。可以提供待验证草案，但必须明确“未核验最新信息”，不得继续生成正式学习契约或声称没有新知识点。

## 2. 发现最新知识点候选

不要只搜索“<领域> 最新”。根据领域选择一手入口，并至少覆盖：

- 当前官方文档导航、功能/概念目录和现行标准目录；
- releases、changelog、迁移指南、废弃/移除公告和安全公告；
- CLI/API 帮助、配置 schema、SDK 或源码中的公开用户入口；
- 官方路线图只用于识别 `planned`，不得当作当前能力；
- 权威研究、标准组织或专业机构近期发布，用于发现新概念和边界变化；
- 独立来源，用于验证成熟度、实际影响或采用情况。

将每个可能影响学习内容的新概念、功能、流程、约束或替代方案登记为候选。只记录版本事件而不提取其带来的知识点，视为未完成。

## 3. 逐项处置

对每个候选记录：名称、发现来源、发布日期/生效日期、适用版本、生命周期、证据、与现有节点的差异，以及唯一处置结果：

- `新增节点`：需要新的行为、心智模型或独立验证标准；
- `修改节点`：改变现有操作、概念、边界、依赖或评价标准；
- `降级/移除`：已废弃、被替代或不再适合作为默认路径；
- `仅作关系变化`：节点仍成立，但前置、接口或应用关系改变；
- `排除`：与领域或学习目标无关，并写明理由；
- `待验证`：证据不足，只进入缺口，不能进入正式路线。

已验证变化只要会改变用户行为、心智模型、依赖关系、适用边界、风险判断或毕业任务，就必须进入公共地图。不是每条新闻都成为知识点，但每个候选都必须有去向。

## 4. 通过条件

以下条件全部满足才可建立学习契约：

- 实际完成联网增量检查，`as_of` 等于当前会话日期；
- `anything-research` 卷宗同时具备稳定结构轨和最新状态轨；
- 最新知识点候选处置表非占位，并覆盖所有发现的候选；确无候选时写明检查入口和“无实质变化”的证据；
- `domain-map.json`、`domain-map.md` 与 `validation.md` 已同步吸收处置结果；
- 已废弃、已移除、实验性和计划中内容没有被当作当前默认能力；
- 向用户报告研究截止日、检查范围、找到的新增/修改/排除项和未闭合缺口。
