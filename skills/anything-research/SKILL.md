# anything-research — 深度调研引擎

调用：`/anything-research <研究问题> [用途=理解|决策] [深度=浅|中|深] [轮数=N]`。省略用途即**理解**、省略档位即**中**。

- **用途=理解（默认）**：帮用户搞懂一个主题——是什么、为什么重要、关键脉络、共识与分歧、该怎么切入。报告侧重知识叙述。
- **用途=决策**：支持具体决策（选型/投入/风险）。报告侧重利弊对垒、风险清单、明确建议。

两种模式：
- **自由模式**（用户直接调用）：问题任意——选型对比、行业调研、技术尽调、事实核查、背景调查。
- **教学五问模式**（被 anything-roadmap 调用）：研究问题固化为五问——① 领域结构与核心问题 ② 公认学习路径（按可信度阶梯：官方路线 > 大学课表 > 高星 awesome > 高信噪比个人文 > 社区共识）③ 权威资源（文档/书/课/视频，含语言）④ 常见误解与难 点 ⑤ 难度与前置依赖。产出必须填满卷宗的"教学预埋"章节。

## 铁律（违反任何一条即失败）

1. **迭代性**：每一轮搜索必须由前轮的**阅读产出**驱动（新线索/新术语/新矛盾），禁止一次性并发撒网后直接综合。每轮在卷宗"迭代轨迹"里记录：搜了什么、由什么线索驱动、砍掉了什么。
2. **交叉验证**：进入"关键发现"的论断须 ≥2 个**相互独立**的来源佐证（同一事件的两篇转载不算独立）；孤证只能进"待验证"，并显式标注"孤证"。
3. **全文级阅读**：佐证基于打开后的**全文**（webReader/Jina 全文），不得基于搜索摘要片段下结论。
4. **矛盾呈现**：信息冲突时不抹平——卷宗"分歧与矛盾"章节让各观点带着各自最强证据对垒，可以给出倾向性判断但必须说明依据与剩余不确定性。
5. **来源分级**：一手（官方/当事人/原始论文）> 二手（转述/评测）> 聚合（awesome/SEO 站）；每条证据标注层级。仿冒站与 SEO 聚合站一律剔除并记入剔除统计。
6. **零幻觉链接**：卷宗中每个 URL 必须真实打开过。curl/直连失败 ≠ 死链——先换通道（本地代理 → web_reader → Jina）重试再判死。
7. **诚实缺口**：查不到的写进"信息缺口"，不编造、不含糊带过。

## 预算常量表（默认值；改此处即改全局默认）

| 档位 | 轮数上限 | 候选上限 | 入卷证据 | 每论断佐证 |
|---|---|---|---|---|
| 浅 | 2 | 25 | ~15 | ≤2 |
| **中（默认）** | **4** | **60** | **~30** | **≤3** |
| 深 | 6 | 100 | ~50 | ≤3 |

- `轮数=N` 显式参数覆盖档位轮数，其余额度按比例折算。
- **收益递减闸**：某轮结束后，关键论断无新增且无新矛盾 → 提前终止，并在卷宗声明"第 N 轮触发递减停"。

## 流程（一站到底）

### 0. 消歧（最多一问）
研究问题有歧义时问一句范围（"性能"→延迟还是吞吐？），答完不再问；无歧义直接开跑。

### 1. 探测搜索通道（先复用，再内置）
先看环境里已安装的搜索类 skill（当前为 agent-reach），跑 `agent-reach doctor --json` 确认哪些通道今天活着。缺席或全死 → 内置 WebSearch/WebFetch；context7 作为编程库文档专线（可用时用）。

| 任务 | 首选 | 降级 |
|---|---|---|
| 通用 web / 官方文档 / 博客 / 社区（间接） | Exa：`mcporter call exa.web_search_exa query="…" numResults=5` | WebSearch |
| GitHub / awesome-list | `gh search repos`（未认证降级 GitHub REST API） | WebSearch |
| YouTube | `yt-dlp --flat-playlist --print "%(title)s\|%(channel)s\|%(view_count)s\|%(url)s" "ytsearch5:…"` | WebSearch |
| B站 | `PYTHONUTF8=1 bili search "…" --type video -n 8`（防 GBK 乱码） | WebSearch |
| 打开读全文 | web_reader MCP → Jina（`curl r.jina.ai/<URL>`）→ WebFetch | — |

官方文档站若提供 `llms.txt` 机器可读索引，优先抓它当结构骨架。

### 2. 迭代调研循环（核心）

每轮执行，直到触发停止闸：

1. **主代理列本轮问题**：首轮来自研究问题分解（自由模式）或五问（教学模式）；后轮来自前轮阅读产出的新线索、新术语、未闭合的矛盾。
2. **子代理扇出搜索**：按路由表并行派发（每个子代理负责一组查询，回报候选清单：URL+标题+一句话摘要，不自行下结论）。
3. **主代理全文阅读与裁决**：打开高价值候选的全文；对每条候选三问——活着？对题？够层级？通过的进证据池；围绕"论断"组织证据（同一条论断的多个佐证归并），标置信度（高=多源一致 / 中=有佐证但有出入 / 低=孤证或推断）。
4. **记录迭代轨迹**：本轮查询、驱动线索、新增论断数、新矛盾、砍掉候选及理由。
5. **生成下一轮问题**：证据池里的缺口与矛盾就是下一轮的输入；没有新问题 → 收益递减闸触发。

### 3. 成稿（双产物：报告给人，卷宗给 AI）
输出目录 `./<主题>-research-<YYYYMMDD>/`，两个产物：

- **`report.md` — 研究报告（主交付物，给人读）**：结构与语气严格按 `references/report-template.md`。铁律：**报告优先**——用户要的是这个。总览一屏可读（主题是什么 + 3-5 条关键洞见 + 一句话建议）；正文叙述体、按用途分侧重；洞见引用卷宗证据编号而非堆表格；必含"共识与分歧"叙述对垒与**综合结论**（所以呢？读者该关注什么）；深入阅读只精选 5-10 条。长度纪律：正文 ~2000-3500 字，密度留给卷宗。
- **`research.md` — 证据卷宗（底座，给 AI 与回查）**：保持 `references/dossier-template.md` 的 schema 不变（研究问题与范围 / 关键发现+证据表 / 分歧与矛盾 / 信息缺口 / 迭代轨迹 / 分级来源清单 / 教学预埋）。正文中文，来源标题保留原文。结尾统计行：候选 X / 全文阅读 Y / 入卷 Z / 剔除 W（死链/不对题/低层级）。

两份产物出自同一证据池：先成卷宗，再从卷宗提炼报告——报告里的每条论断都能按编号回溯到卷宗证据。

### 4. 交付
在对话中明确列出 report.md 与 research.md 两个产物的完整绝对路径，并把文件发送给用户（report 在前——它是主交付物）。

## 集成约定（供 anything-roadmap 调用）

- 教学五问模式下，research.md（roadmap 消费的契约不变）与 report.md 都写入 roadmap 的输出目录 `<领域>-roadmap-<YYYYMMDD>/`；复用检测仍只认 research.md。
- 复用检测由 anything-roadmap 侧执行（同领域、7 天内的 `-research-` 卷宗），本 skill 不管复用。
- 本 skill 对 anything-research 自身而言无任何硬依赖：agent-reach / web_reader / context7 全部"探测→可用则用"。

## 边界
- 浅查（单平台快速抓取、查一条推文/一个视频）→ agent-reach。
- 制定学习大纲、产出 roadmap.md/roadmap.html → anything-roadmap（本 skill 只到卷宗为止）。
- 无工具环境的方法论投影：`references/dossier-template.md` 附带可复制的无工具版提示词（其产物是报告体，正好对应 report.md 的角色）。
