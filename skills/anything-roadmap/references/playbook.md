# anything-roadmap 方法论（无工具环境版）

> **用途**：把下面的「提示词模板」复制给任何 AI（网页版 Claude、ChatGPT、Gemini 等），让它按本 skill 同样的方法为你制定学习路线。
>
> **⚠️ 降级声明（使用前必读）**：
>
> 本方法论是 anything-roadmap skill 的**简化投影**，专为无工具调用能力的环境设计。与完整 skill 版的核心差异：
>
> | 能力 | 完整 skill 版 | 本方法论（无工具版） |
> |------|--------------|---------------------|
> | 链接验证 | ✅ 100% 逐条打开验证（三通道接力） | ❌ 依赖 AI 的搜索能力或训练数据 |
> | 前人路线搜索 | ✅ 真实搜索（Exa/gh/yt-dlp/bili） | ⚠️ 视 AI 是否有联网搜索 |
> | 来源可信度 | ✅ 三问准入（活着/对题/权威） | ❌ 需要**你人工抽查**验证 |
> | 交互 HTML | ✅ 单文件知识星图，离线可开 | ❌ 仅 Markdown 输出 |
>
> **使用建议**：
> - 生成后**必须人工抽查**至少 20% 的链接，确认真实有效
> - 优先选择有实时搜索功能的 AI（如 Perplexity、联网版 ChatGPT）
> - 将 AI 给出的「未核验」来源当作线索，自行搜索验证后再使用

你是一位系统化课程设计师。请为「**<领域>**」制定完整的学习路线。

**我的背景**：<背景>（如果是零基础就写"零基础"）

## 工作流程（严格按顺序执行）

### 第 1 步：消歧与确认（最多问 2 个问题）
1. 如果领域名称有歧义（如"支付"可能指支付系统开发或支付业务流程），问一句话澄清范围
2. 如果我没说明背景，再问一句"你有相关基础吗？"
3. **问完这两个后就不要再问了**，直接开始制定

### 第 2 步：调研现成的学习路线（骨架来源）
**不要凭空编造路线结构**。先搜索现成的学习路线设计，按可信度排序：

1. **官方路线**（最优先）：该技术官方网站的 Learning Path、Getting Started、Tutorial 系列
2. **大学课表/知名课程**：MIT/Stanford 等课程大纲、Coursera/edX 课程目录
3. **高星 awesome 列表**：GitHub 上 stars >1000 的 `awesome-<domain>` 资源列表
4. **高质量个人路线**：知名从业者的系统学习指南（非零散博客）
5. **社区共识**：Reddit/知乎/Stack Overflow 上高赞的学习路径讨论

**搜索要求**：
- 如果你有联网搜索：真实搜索并引用你找到的链接，最后附上参考路线清单（标题 + 链接 + 一句话点评）
- 如果你没有联网：列出你知道的权威来源（如"React 官方文档 Learn 章节"），**全部标注「未核验」**警告我
- 如果搜不到 ≥2 条可信路线：改用该领域**官方文档的目录结构**组织大纲，并明确告诉我"该领域搜不到足够现成路线，已按官方文档结构组织"

### 第 3 步：生成四级大纲
按 **模块 → 主题 → 章节 → 知识点** 四级结构组织：

**大纲要求**：
- **模块**（Module，M1/M2/M3...）：按学习顺序编号，体现先后依赖
- **主题**（Topic）：每个模块下的知识分类
- **章节**（Chapter）：主题的细分
- **知识点**（Knowledge Point）：最小学习单元，每个配 1-3 个学习源

**必须包含的部分**：
1. **全局地图**（开头）：
   - 领域整体面貌（核心问题是什么）
   - 模块为什么这么切（拆分依据）
   - 模块间的关联关系（如"M1 的一致性理论是 M2 存储引擎的基础"）

2. **每个模块**：
   - 模块编号（M1, M2...）和名称
   - 为何这么切（设计理由，1-2 句话）
   - 参考了哪些前人路线（标注序号如 [R1] [R2]）
   - 2-3 个动手练习

3. **每个知识点**：
   - ≤3 个学习源，媒介混搭（官方文档 / 博客 / 视频 / 网站）
   - 英文权威源为主、中文入门材料为辅（标题保留原文）
   - 格式：`[类型·语言 标题](链接)` 如 `[DOC·EN Getting Started](url)`
   - 类型标签：DOC（文档）/ BLOG（博客）/ VID（视频）/ SITE（网站）

**不要包含**：
- ❌ 详细的时间表（"第1周学X"）
- ❌ 打卡计划或进度跟踪
- ❌ 验收标准或考试安排

### 第 4 步：控制规模
- 全部学习源总数控制在 **40 个左右**
- 宁缺毋滥，只给高质量的源
- 每个知识点最多 3 个源，重要的知识点可以 3 个，次要的 1-2 个即可

### 第 5 步：Markdown 输出格式

```markdown
# <领域> 学习路线

> **生成日期**：<今天日期>  
> **制图模式**：<前人路线为骨 / 官方文档回退>  
> **受众**：<基础假设>  
> **来源状态**：<已联网搜索并验证 / 基于训练数据未核验>

## 0. 全局地图

### 0.1 领域面貌
<这个领域是什么，核心问题，为什么重要>

### 0.2 模块拆分依据
<为什么按这个方式切分模块>

### 0.3 模块间关联
- **M1 ⇄ M2**：<关联说明>
- **M2 ⇄ M3**：<关联说明>

## M1. <模块名>
> **为何这么切**：<1-2句话说明此模块设计理由>  
> **参考路线**：[R1] [R2]

### 1.1 <主题名>
#### 1.1.1 <章节名>
- **<知识点>**
  - [DOC·EN Title](url) — <一句话说明>
  - [VID·中 标题](url) — <一句话说明>

### 1.X 勘测练习
1. <动手练习描述>
2. <动手练习描述>

## M2. <模块名>
...

## 附录 A：参考图源（前人路线）
1. **[官方]** [标题](链接) — <一句话点评>
2. **[课表]** [标题](链接) — <一句话点评>
3. **[社区]** [标题](链接) — <一句话点评>

## 附录 B：生成说明
<说明制图模式、是否联网搜索、来源验证状态、受众假设>
```

## 收到结果后的验证清单

AI 生成结果后，你需要人工检查：

- [ ] **抽查链接有效性**：随机选择至少 20% 的链接（约 8-10 个），确认可以打开且内容对题
- [ ] **检查来源标注**：确认 AI 是否明确标注了「未核验」的来源
- [ ] **评估路线可信度**：
  - 是否引用了官方文档或知名课程？
  - 模块划分是否符合该领域的常见认知？
  - 学习顺序是否合理（基础 → 进阶 → 高级）？
- [ ] **识别潜在问题**：
  - 死链（404/403）
  - 过时内容（发布日期过早，如 2015 年的前端框架教程）
  - 同名异义（如搜 Hermes 结果混入 JS 引擎和机械臂的内容）
  - SEO 聚合站（标题党、AI 生成的低质内容农场）
- [ ] **补充与修正**：
  - 缺失重要知识点？自行补充
  - 顺序不合理？调整模块顺序
  - 来源失效？搜索替代资源

## 提高输出质量的技巧

### 技巧 1：分阶段调用
如果一次性输出质量不理想，可以分步骤让 AI 完成：

**第一轮**：只要求调研路线
```
请帮我搜索「<领域>」的现成学习路线，包括：
1. 官方 Learning Path
2. 知名大学课程大纲
3. GitHub awesome 列表
4. 高赞社区讨论

列出标题、链接和一句话点评。
```

**第二轮**：基于路线生成大纲
```
基于以下路线，为「<领域>」制定四级大纲（模块→主题→章节→知识点）：
[粘贴第一轮结果]

要求：[复制提示词模板中的大纲要求部分]
```

**第三轮**：为每个知识点配源
```
为以下知识点配置学习源（每个 ≤3 个，英文权威 + 中文入门）：
[粘贴需要配源的知识点列表]
```

### 技巧 2：针对冷门领域
如果 AI 表示搜不到现成路线，可以追问：
```
了解。请改为：
1. 找到「<领域>」的官方文档站点
2. 以官方文档的目录结构为骨架组织大纲
3. 在开头明确声明"该领域未找到现成学习路线，已采用官方文档结构"
```

### 技巧 3：要求 AI 自查
在提示词末尾加上：
```
生成后，请自己检查：
1. 是否有链接是你编造的？如有，标注「未核验」
2. 是否有知识点缺少学习源？如有，补充或删除该知识点
3. 模块总数是否 ≤6 个？（超过容易学不完）
4. 学习源总数是否 ≤40 个？（超过容易信息过载）
```

## 常见问题

### Q1：AI 给的链接大部分是错的怎么办？
**A**：这说明该 AI 在"幻觉"（编造不存在的链接）。建议：
1. 换一个有实时搜索功能的 AI（如 Perplexity、联网版 ChatGPT）
2. 或者只让 AI 给大纲结构，你自己去搜索每个知识点的学习源
3. 明确要求：「如果你不确定链接是否存在，就不要给，标注为待查找」

### Q2：AI 给的路线太浅/太深怎么办？
**A**：在背景描述中更具体：
- 太浅 → 「我已系统学过 X，重点想深入 Y 和 Z 方向」
- 太深 → 「我是完全零基础，需要从最基础的概念开始」

### Q3：领域名称有歧义，AI 理解错了？
**A**：在领域名称后加括号澄清：
- 「支付（指支付系统架构开发，不是业务流程）」
- 「Rust（编程语言，不是游戏 Rust）」

### Q4：想要特定方向的路线怎么办？
**A**：在背景中说明目标：
- 「我想找前端工程师岗位，请侧重工程化和框架」
- 「我做科研用，请侧重理论基础和论文阅读」

### Q5：生成的路线太长，学不完？
**A**：追加要求：
```
这个路线太长了。请精简到：
- 模块数 ≤4 个
- 每个模块知识点 ≤6 个
- 只保留核心必学内容，去掉可选进阶部分
```
